# Flowcharts and tables

Use a flowchart for data flow, model stages, algorithm branches or decision logic with at least three meaningful nodes. Keep node labels short and make branches semantically distinct. Do not reproduce every implementation statement.

Use a table for exact values, symbols, parameters, scenario outputs or model comparisons. Include units in headers, align decimals, apply meaningful precision and explain unavailable values. Avoid vertical rules and decorative cell colors; use grouping, spacing and restrained rules for hierarchy.

A figure and table should not duplicate the same message. Keep the chart for shape/comparison and the table for exact lookup only when readers need both.
