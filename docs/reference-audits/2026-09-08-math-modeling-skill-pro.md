## Independently rewritten ideas adopted

The user selected six general workflow concepts for independent implementation:

1. stage-level plus whole-chain structural retrieval;
2. candidate plans layered as robust baseline, competition-strength improvement, and falsifiable innovation;
3. explicit propagation of predictive uncertainty into downstream optimization;
4. validation separated into internal, stage, comparative, and uncertainty/end-to-end layers;
5. innovations tied to a named baseline defect and a discard threshold;
6. durable producer-consumer handoff contracts with schema, units, grain, version and leakage boundary.

These concepts were expressed from first principles and fitted to this suite's existing low-coupling architecture, evidence ledger, `QUESTION GRAPH`, `MODEL SUMMARY`, tests, and corpus search.

## Deliberately not adopted

- a single monolithic competition Skill;
- a mandatory large fixed output structure for every narrow request;
- external case libraries or claimed case counts as local evidence;
- external templates, scripts or code scaffolds;
- topic-name lookup in place of mathematical-structure matching;
- any claim that the external repository's contents validate this suite.

## Verification rule

Only behavior demonstrated by this repository's own tests and pressure-test artifacts is reported as supported. External repository descriptions are not counted as local verification evidence.
