# CUMCM 三层专家 Skill 体系设计规格

日期：2026-09-07  
状态：待用户复核  
范围：2020–2025 年 CUMCM A/B/C 题，A 题为重点

## 1. 目标

在当前工作区建立一套可被 Codex 发现、可长期维护、可验证的 CUMCM 专家 Skill 体系，使其能协同完成赛题理解、数学建模、Python 实现、可视化、论文写作和最终一致性审查。

系统学习的是“数学结构在什么条件下适合什么方法，以及如何证明方法有效”，不是历史赛题与模型名称的机械映射，也不复制优秀论文。

## 2. 已选择的方案

采用“广覆盖、深挖 A 题”的证据优先方案：

1. 覆盖 2020–2025 年全部 18 道 A/B/C 赛题。
2. 完整分析当前工作区可访问的 9 篇 2024 优秀论文。
3. 使用中国大学生在线官方论文展示补充其他年份论文；优先深读 A 题。B/C 每年均至少覆盖一篇，并按数学结构分层扩充；连续三篇新增论文都没有带来新的问题结构、模型选择条件或验证规则时，视为首版达到规律饱和。
4. 参考 `math-modeling-skill-pro` 的案例检索、证据溯源和自动验证思路，允许读取其中公开可访问的数据作研究证据，但不复制其案例卡、代码、模板或专有表述。
5. 将 2025 A 题及对应优秀论文保留为 hold-out：建成 Skill 后先独立作答，再读取论文或讲评进行对照。

未选择的方案：

- 全量逐页 OCR 2020–2025 所有展示论文：成本高、图片版论文识别噪声大，不作为首版完成条件。
- 只使用本地论文：不能满足跨年度和外部证据要求。
- 单一巨型 Skill：职责耦合、加载成本高，违背三层架构要求。

## 4. Skill 边界与接口

### 4.1 `cumcm`

负责：读取材料、问题结构化、小问依赖图、任务分类、阶段调度、质量门和最终一致性检查。

不负责：讲解具体算法、编写绘图样式、重新计算建模结果或代替论文专业写作。

向 `cumcm-modeling` 传递问题卡；接收模型摘要。向 `cumcm-visualization` 传递图表请求；向 `cumcm-thesis` 传递可追溯的模型、结果和图表信息。

### 4.2 `cumcm-modeling`

负责：数据审计、数学形式化、候选模型、baseline、算法、Python 实现、求解、验证、敏感性、鲁棒性与不确定性。

不负责：决定论文叙事或完整绘图规范。

核心输出采用 `MODEL SUMMARY` 契约，至少包含目标、变量、假设、baseline、主模型、方程、算法、参数、验证、敏感性、关键结果和限制。

### 4.3 `cumcm-visualization`

负责：EDA、图表选择、科研绘图、流程图、结果图、表格和图表审查。

不负责：重新选择预测、评价或优化模型。

输入采用 `FIGURE REQUEST` 契约，明确图的目的、数据、主要信息、变量、单位、推荐图型和输出格式。

### 4.4 `cumcm-thesis`

负责：摘要、重述、分析、假设、符号、建模表达、求解表达、结果解释、评价、LaTeX 与全文审稿。

不负责：重新计算模型或捏造缺失数字。

写作链为：问题本质 → 资料依据 → 候选方法 → 现实简化 → 针对性优化 → 验证和结果。允许自然变体，避免机械重复“针对问题一”。

## 5. 语料与证据处理

### 5.1 赛题卡

每道题记录：年份、题号、标题、现实背景、小问、输入输出、变量、约束、数据结构、依赖关系、数学结构标签和潜在验证方式。

### 5.2 论文卡

每篇论文记录：来源、年份、题号、问题结构、各小问目标、假设、数据处理、baseline、模型、算法、验证、敏感性、图表、结果、优缺点、可迁移规律和题目特有技巧。

卡片中的每个方法性结论标记证据等级：

- `observed`：论文中可直接确认。
- `inferred`：根据公式、图表或方法链推断。
- `expert-rule`：综合多篇论文与一般建模原则形成。
- `unverified`：来源不可访问或 OCR 无法可靠确认。

### 5.3 参考仓库边界

`math-modeling-skill-pro` 只用于：

- 发现候选案例与结构标签；
- 对照语料覆盖和检索设计；
- 检查是否遗漏常见验证、模型边界或代码骨架类别。

不将其 139 张案例卡、知识文档、脚本或模板复制进本项目。所有写入本项目的结论必须能由官方赛题、官方论文、本地论文或独立建模原理重新支持，并在证据台账中注明来源。

## 6. A 题重点策略

A 题单独建立跨年结构分析，重点识别：

- 机理方程、几何、物理过程与工程约束如何数学化；
- 参数估计与边界/初始条件怎样连接数据；
- 数值方法、优化或仿真何时作为机理模型的求解层；
- 简化假设会带来什么偏差；
- 如何设计量纲、守恒、极端情况和扰动验证；
- 如何从基础机理模型定位缺陷并做可验证改进。

B/C 题保持完整覆盖，用于补充离散优化、统计学习、评价决策和数据治理规律。

## 7. 模型选择系统

模型选择按以下顺序进行：

```text
数学结构
→ 数据条件
→ 建模目标
→ 解释性要求
→ 决策变量与约束
→ 规模与计算预算
→ 不确定性
→ 候选模型
→ baseline 与验证设计
→ 最终选择
```

每个候选方案必须说明适用条件、排除条件、所需数据、关键假设、验证办法和失败风险。复杂模型必须说明相对 baseline 的真实收益；组合模型必须说明每一部分解决的明确缺陷。

## 8. 脚本设计

首版只实现可验证、可复用的脚本：

- `build_inventory.py`：扫描题目、论文、附件及格式，输出稳定索引。
- `search_cases.py`：按结构标签、数据条件和目标检索案例卡，不按关键词直接决定模型。
- `validate_corpus.py`：检查卡片字段、来源、重复项和证据状态。
- `data_profile.py`：生成数据形状、字段、类型、缺失、重复、异常和基础统计报告。
- `validation_utils.py`：提供数据切分、回归/分类误差、约束违反和扰动实验的基础工具。
- `plot_style.py` 与 `plot_helpers.py`：提供中文、黑白打印、矢量导出和常用结果图支持。
- `validate_skills.py`：检查 frontmatter、链接、入口长度、未完成占位符和跨 Skill 重复内容。

所有脚本先写失败测试，再实现最小可用功能；外部论文下载或 OCR 不作为普通使用路径的运行依赖。

## 9. 测试设计

### 9.1 RED

使用附件指定的 10 类压力场景测试无 Skill agent，记录其实际失败：过度推荐复杂模型、时序随机切分、默认熵权 TOPSIS、线性整数规划滥用 GA/PSO、忽略重复运行、高 R² 直接下结论、无目的绘图、模板化摘要、空泛优缺点和伪创新。

### 9.2 GREEN

逐个实现并验证四个 Skill。一个 Skill 未通过其对应场景前，不进入下一个 Skill。

### 9.3 REFACTOR

记录新漏洞，只针对观察到的失败补充决策规则，避免无限扩张 `SKILL.md`。

### 9.4 Hold-out

不向 Skill 暴露 2025 A 题优秀论文方法，要求其独立输出：题型、小问依赖、形式化、baseline、主模型、算法、验证、敏感性、图表和论文方案。之后与官方讲评或论文对照，差异按“是否满足数学结构与约束”评估，不以是否使用同一模型作为唯一标准。

## 10. 验收标准

完成时必须满足：

1. 四个 `SKILL.md` frontmatter 有效，description 只描述触发条件。
2. 专业知识不在多个入口重复，references 可从入口按条件发现。
3. 18 道 2020–2025 A/B/C 赛题均有索引或问题卡；缺失证据明确标记。
4. 本地 9 篇论文均有结构化卡片；外部论文覆盖跨年份、跨题号且 A 题优先。
5. 每条代表性可迁移规律能追溯到语料或明确标为专家规则。
6. pressure tests 有 RED 与 GREEN 对照结果。
7. 2025 A hold-out 有独立方案、对照评价和限制说明。
8. 新脚本测试通过，并能在当前环境运行。
9. Skill 路径、引用、模板和脚本通过自动验证；实际发现能力进行可观察检查。
10. 最终报告包含 Skill Tree、Corpus Summary、Extracted Patterns、职责、测试结果、hold-out 结果和 Known Limitations。

## 11. 失败处理与限制

- PDF 文字层缺失时允许 OCR，但保留 OCR 置信度与人工复核标记。
- 官方论文为图片展示或链接失效时，记录元数据和不可访问状态，不推断具体方法。
- 缺少论文源代码时，不声称论文程序可复现。
- 外部参考仓库的统计只作为线索，不能替代独立证据验证。
- 当前目录不是 Git 仓库，因此不能提交或推送；其余验收不因此跳过。
